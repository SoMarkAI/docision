# Licensing and third-party components

The deployment source is distributed under the repository's Apache License 2.0;
`LICENSE` is an unchanged copy of the parent repository license. This statement
covers the application source, not user documents, model weights, training data,
trademarks, or independently distributed dependencies. Preserve applicable
copyright, license and attribution notices when distributing derivatives.

## Installed dependencies

The source overlay contains no vendored Python wheels or native libraries.
Installers obtain these independently. The principal components are:

| Component | Upstream license / review note |
|---|---|
| PyTorch and Torchvision | BSD-style; their wheels include additional third-party notices |
| Transformers, Accelerate, Safetensors | Apache-2.0 |
| Pillow | MIT-CMU; binary wheels can include additional libraries |
| pypdfium2 | Apache-2.0 / BSD-3-Clause; bundled PDFium and dependencies have their own notices |
| Official MCP Python SDK | MIT |
| PyPA virtualenv bootstrap | MIT; bundled seed packages retain their own licenses |

The complete installed environments also contain transitive dependencies. For
example, certifi uses MPL-2.0, tqdm reports MPL-2.0 AND MIT, and regex reports
Apache-2.0 AND CNRI-Python. CUDA installations include NVIDIA components with
proprietary licenses. Do not label an entire bundled runtime as Apache-2.0.
A source release which installs dependencies is different from redistributing
those binaries. Before distributing an installer with bundled wheels, a Docker
image, or a complete environment, separately review each shipped version's
LICENSE/NOTICE files and NVIDIA redistribution terms.

Generate metadata inventories of the actual installed environments with:

```bash
.venv/bin/python release/dependency_inventory.py > model-licenses.json
.mcp-venv/bin/python release/dependency_inventory.py > mcp-licenses.json
```

Metadata can be missing or abbreviated. These inventories locate license files;
they do not replace reading those files. Store audit outputs in `validation/`,
not in the source package.

## Models and data

Model download: [SoMarkAI/Docision-1.0](https://huggingface.co/SoMarkAI/Docision-1.0)

Acceptance fixtures generated by `release/smoke.py` are synthetic images and a
PDF drawn by the script. They contain no real contract, signature or person.
Parent-repository artwork and existing example documents require their own
provenance review; they are not included in the deployment overlay.
